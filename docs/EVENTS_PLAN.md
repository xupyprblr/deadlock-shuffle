# План: движок ивентов и первый ивент «Катакомбы»

Статус: план, 18.11.2026. Код не начат. Пункты с ❓ ждут Алекса.

## 0. Решения Алекса (18.11.2026)
- Интеграция с Deadlock **с первого ивента**: задания основаны на матчах игрока, но связаны с сайтом
  (сборку берёшь у нас — играешь её в игре). Значит, вход через Steam нужен сразу.
- Механика первого ивента — **выбор на каждом этапе из 3–4 вариантов**: конкретный герой или **семейство героев**
  (крылатые, в маске, женщины и т.п.). Выбрал — играешь им; прошёл — следующий этап.
- Движок гибкий: следующие ивенты (боевой пропуск, сезонные треки) — новым конфигом, без переписывания.

## 1. Зачем
Удержание и возвраты: у человека есть причина зайти завтра — посмотреть, засчитались ли матчи, выбрать следующий
этап, забрать награду. Ивент связывает сайт и игру: сайт выдаёт сборку → игрок играет её в Deadlock → сервер видит
матч и продвигает его по ивенту → человек возвращается на сайт за следующей сборкой.

Механика в жанре событийной карты/пропуска общая; название, сюжет и арт — свои (Deadlock-эстетика: подземелья
под оккультным Нью-Йорком). Арт и интерфейс чужих игр (Dota 2 и др.) не копируем и в референсы не даём.

## 2. На что опираемся (уже есть)
- Cloudflare Worker + D1 (`stats/`): счётчик, админка `/admin/`, настройки. Ивенты строим тем же стеком.
- `track()` — все действия на сайте уже событиями: `roll`, `slots_spin`, `to_game` (с героем, сборкой, разделом)…
- Фаза 2.0: `journal.js` (журнал забранных сборок), `match.js` (чистые функции: SteamID → account_id,
  события игрока в матче, `compareBuild` — сколько предметов сборки куплено, `RANDOM_MIN`/`FULL`),
  `my.html` (матчи игрока из Deadlock API). Эту логику переносим на сервер — она и есть проверка заданий.

## 3. Ключевая механика: «забрал на сайте → сыграл в игре»
Каждый этап засчитывается **матчем в Deadlock**, но только если сыграна **сборка, забранная на нашем сайте**:
1. Игрок на этапе выбирает вариант (герой / семейство).
2. Крутит на сайте (рандом или казино) сборку на подходящего героя и жмёт «Скопировать в игру».
   Сайт отправляет на сервер **забор** (`POST /take`: герой, предметы, раздел, время по часам сервера) — это
   серверный журнал фазы 2.1.
3. Играет матч этим героем. Сервер (по расписанию или по кнопке «Проверить матчи») берёт матчи игрока из
   Deadlock API и сопоставляет с заборами (`compareBuild` ≥ `RANDOM_MIN` предметов, матч после забора, в окне 7 дней).
4. Этап засчитан. **Звёзды этапа** (как уровни сложности): ★ сыграл, ★★ победил, ★★★ собрал затар полностью (`FULL`).
   Звёзды дают очки трека; для прохода дальше достаточно ★.

Так сайт обязателен для прогресса (без забора матч не считается), а прогресс — честный (матчи проверяет сервер).

### 3.1 Семейства героев
Справочник `events/hero-tags.json` (ведём руками, правится в админке): тег → список героев, RU/EN название, иконка.
Примеры ❓: «Крылатые», «В масках», «Женщины», «Стрелки», «Маги духа», «Танки», «Призыватели», «Нежить».
Вариант этапа = `{ hero: id }` или `{ tag: "masked" }`; выбор из 3–4 вариантов генерируется из пула этапа
детерминированно (`hash(uid, этап)`), чтобы у разных игроков были разные развилки, но стабильные при перезаходе.

## 4. Архитектура
```
Браузер (сайт)                          Cloudflare
 ├─ «Войти через Steam» ───────────▶  Worker «randomlock-api» (новая папка api/)
 ├─ «Скопировать в игру» → POST /take   ├─ Steam OpenID → сессия (подписанный токен)
 ├─ страница /event/, виджет, тосты     ├─ движок ивента (конфиг + заборы + матчи)
 └─ «Проверить матчи» → POST /sync      ├─ D1 «randomlock-events»
                                        └─ Cron: матчи активных игроков из Deadlock API
```
- **Отдельный Worker и база** от счётчика статистики: тут личные данные и проверки, там анонимные итоги.
- **Вход через Steam (OpenID 2.0):** без паролей и без ключа Steam Web API; получаем SteamID64 → account_id.
  Сессия — подписанный токен (HMAC), хранится в браузере. Без входа ивент можно смотреть, но не проходить.
- **Почему не VPS:** Cloudflare уже работает, бесплатен на старте, Cron есть. VPS фазы 2 можно добавить позже.
- ⚠️ Лимит записи D1 на бесплатном тарифе общий на аккаунт (100 тыс. строк/сутки) — к запуску на main
  нужен Workers Paid ($5/мес).

### 4.1 Данные (D1)
| Таблица | Что хранит |
|---|---|
| `users` | account_id (Steam), created_at, last_seen, бан |
| `takes` | id, account_id, hero_id, items (JSON), source (рандом/казино/раздел), build_id (для казино), taken_at |
| `matches` | account_id, match_id, hero_id, start_time, win, разбор (купленные предметы), checked_at — кэш, чтобы не тянуть матч дважды |
| `progress` | account_id, event_id, stage, выборы по этапам, звёзды, очки, уровень трека, забранные награды (JSON) |
| `credits` | account_id, event_id, stage, match_id — какой матч закрыл этап (матч засчитывается один раз) |

### 4.2 Конфиг ивента
`events/catacombs.json` в репозитории (ревью через git), позже — правка в админке.
```jsonc
{
  "id": "catacombs-1",
  "title": { "ru": "Катакомбы", "en": "The Catacombs" },
  "start": "…", "end": "…",
  "points": { "ru": "Свечи", "en": "Candles" },
  "stars": { "play": 1, "win": 2, "full": 3 },         // за что звёзды этапа
  "starPoints": [0, 100, 150, 250],                   // очки за 1/2/3 звезды
  "stages": [
    { "id": 1, "choices": 3, "pool": [{ "tag": "masked" }, { "tag": "winged" }, { "hero": 15 }, …] },
    …
    { "id": 8, "boss": true, "choices": 1, "pool": [{ "tag": "any" }], "need": "win" }
  ],
  "track": [ { "points": 200, "reward": "frame-bone" }, … ],
  "rewards": { "frame-bone": { "type": "card_frame", "art": "img/events/catacombs/frame-bone.webp" }, … },
  "bonus": [ { "on": "to_game", "where": { "source": "casino" }, "points": 10, "daily": 3 } ] // мелкие сайтовые бонусы
}
```
Тип прогресса задаётся конфигом: `stages` (катакомбы), позже `quests` (ежедневные/недельные задания пропуска) —
движок поддерживает оба, на первом ивенте используем `stages` + немного сайтовых `bonus`.

### 4.3 API Worker
| Метод | Что |
|---|---|
| `GET /auth/steam`, `/auth/steam/return` | вход через Steam, выдача сессии |
| `GET /me` | профиль, активный ивент, прогресс (для виджета) |
| `GET /event/:id` | конфиг + мой прогресс, текущий этап, мои варианты выбора |
| `POST /event/:id/choose` | выбрать вариант этапа |
| `POST /take` | забор сборки «в игру» (из рандома и казино) |
| `POST /sync` | «Проверить матчи» — не чаще раза в 5 мин на игрока |
| `POST /event/:id/claim` | забрать награду трека |
| Cron (каждые 30–60 мин) | матчи игроков с открытым этапом и заборами за 7 дней |
| `GET /admin/events/:id` | участники, этапы, выбор вариантов, удержание (по ключу админки) |

### 4.4 Deadlock API — главный риск
- Матчи берём `match-history` по account_id и метаданные матча (покупки) — логика `my.js`/`match.js`.
- Лимиты API ~30 запросов/мин с IP, а у Worker IP общие у Cloudflare. Меры: кэш матчей в `matches`,
  проверять только игроков с открытым этапом и свежими заборами, пачками, Cron + ручная кнопка с лимитом;
  ❓ написать авторам deadlock-api про ключ/повышенный лимит для проекта.
- Не каждый матч есть в API (нужен разбор записи) — честно пишем «матч может появиться с задержкой», кнопка «Проверить».

## 5. Фронтенд
1. **Страница `/event/`** (вкладка/баннер на главной и в казино):
   - баннер с таймером до конца, «Войти через Steam»;
   - **карта Катакомб**: этапы-комнаты сверху вниз, пройденные со звёздами, текущий открыт;
   - **текущий этап**: 3–4 карточки выбора (портрет героя или эмблема семейства + герои семейства);
     после выбора — подсказка «Возьми сборку» с кнопками «Рандом на этого героя» / «Казино на этого героя»
     (сайт откроется с нужным героем/пулом), статус «Ждём матч… Проверить матчи»;
   - **трек наград** по очкам (свечам), кнопки «Забрать».
2. **Виджет** в шапке главной и казино: «Катакомбы · этап 3 · ★★».
3. **Тосты**: «Сборка засчитана для этапа 3 — сыграй её в Deadlock», «Этап пройден! ★★ +250 свечей».
4. **Награды-косметика на сайте**: рамки карточек, скины табло/корпуса автомата, титул, лого в пул пасхалки, звуки.
5. **Админка**: блок «Ивенты» — участники, распределение выборов, прохождение этапов, D1/D7-возвраты; редактор тегов героев.
6. RU/EN, светлая тема, телефон от 360 px; CSP — адрес нового Worker во все страницы.

### 5.1 Арт
- Портреты героев/предметов — из Deadlock API.
- Свой арт через Codex (gpt-6-astra, high), пайплайн как `slot_machine/`: фон карты (спуск под город), комнаты-этапы,
  эмблемы семейств, рамки/скины наград, баннер, иконка «Свечи». Сырьё не в git, нарезка скриптом в `public/img/events/catacombs/`.

## 6. «Катакомбы» — тестовый ивент
- ❓ Длительность: 2–3 недели (этап = минимум один матч, нужен запас на то, что матчи появляются в API с задержкой).
- **8 этапов** (7 обычных + босс). На этапе выбор из 3 вариантов (герой или семейство), у босса — «любой герой, но победа».
- Звёзды: ★ сыграл сборку с сайта, ★★ победил, ★★★ собрал затар полностью.
- **Трек:** 8–10 наград по свечам; финальная — эксклюзивный скин автомата.
- Мелкие сайтовые бонусы свечей (лимит в день): забрать сборку в казино, поделиться ссылкой команды.

## 8. Метрики
доля открывших ивент; доля вошедших через Steam; заборы → засчитанные матчи (конверсия «сайт → игра»);
пройденные этапы; D1/D7 возвраты участников против остальных; распределение выборов (какие семейства популярны).

## 9. Риски
- **Deadlock API**: лимиты и задержка появления матчей (см. 4.4).
- **Личные данные**: SteamID, матчи, заборы — обновить текст о данных на сайте, удаление по запросу.
- **Лимиты D1** — Workers Paid к релизу.
- **Восприятие «казино»**: награды бесплатные, не за деньги.
